# 017 - BSON, ObjectId, and Document Shape: Questions and Answers

Use these questions to review BSON values, ObjectId identifiers, dates, and consistent MongoDB document design. Each answer includes a short explanation.

Related lesson: [017 - BSON, ObjectId, and document shape](../lessons/017-bson-objectid-and-document-shape.md)

## Multiple-choice questions

### 1. What does BSON describe in MongoDB?

- A. A binary representation used for MongoDB documents
- B. A browser stylesheet
- C. A SQL query language
- D. A JavaScript package manager

**Answer: A.** MongoDB represents stored documents as BSON. Tools may display them using JSON-like syntax.

### 2. Which statement best describes BSON compared with standard JSON?

- A. BSON supports additional types, including ObjectId and Date.
- B. BSON only supports strings.
- C. BSON is a format for browser styles.
- D. BSON cannot represent arrays.

**Answer: A.** BSON preserves common document structures and also has types that standard JSON does not represent directly.

### 3. Which value is an ObjectId rather than a string?

- A. `ObjectId("507f1f77bcf86cd799439011")`
- B. `"507f1f77bcf86cd799439011"`
- C. `"ObjectId"`
- D. `507f1f77bcf86cd799439011` as an unquoted bare token

**Answer: A.** The constructor-like display indicates a BSON ObjectId value. A quoted hexadecimal sequence is a string.

### 4. How many bytes does an ObjectId contain?

- A. 4 bytes
- B. 8 bytes
- C. 12 bytes
- D. 24 bytes

**Answer: C.** An ObjectId is 12 bytes. It is commonly displayed as 24 hexadecimal characters because each byte is shown with two hex characters.

### 5. What are the components of a standard ObjectId?

- A. A timestamp, a random value, and a counter
- B. A username, a password, and a role
- C. A database name, collection name, and field name
- D. A URL, a port, and a protocol

**Answer: A.** Its 12 bytes contain a 4-byte timestamp in seconds, 5 random bytes, and a 3-byte counter.

### 6. What can the timestamp portion of an ObjectId help you estimate?

- A. Approximately when the ObjectId was generated
- B. The exact time a database write was durably committed
- C. The user's local timezone
- D. The document's expiration date

**Answer: A.** The timestamp is useful for a rough generation-time estimate, but it does not replace an explicit application timestamp.

### 7. Are ObjectIds guaranteed to sort in exact creation order?

- A. Yes, across every process and machine
- B. No. They are roughly ordered, but not a strict global sequence.
- C. Yes, if the collection has fewer than 100 documents
- D. No. ObjectIds contain no time-related component

**Answer: B.** Their timestamp has one-second precision, and values can be generated by different clients with different clocks and random components.

### 8. What is a clear field to store an application's creation time?

- A. `createdAt` with a BSON Date value
- B. The `_id` field only
- C. A random string in a field named `time`
- D. An array of unrelated identifiers

**Answer: A.** Store the application event time explicitly as a Date when the application needs that information.

### 9. What does MongoDB require for each document in a collection?

- A. A unique `_id` field
- B. A `password` field
- C. A `createdAt` field
- D. A `name` field

**Answer: A.** Each document has a unique `_id`. A client can provide it; otherwise, a driver or MongoDB tooling commonly creates an ObjectId.

### 10. What may a Node.js MongoDB driver do if an inserted document omits `_id`?

- A. Generate an ObjectId for `_id`
- B. Remove every other field
- C. Convert the document to HTML
- D. Reject every insert

**Answer: A.** The driver normally supplies an ObjectId when the inserted document does not include `_id`.

### 11. Which pair has different BSON types?

- A. `42` and `"42"`
- B. `true` and `false`
- C. `"MongoDB"` and `"BSON"`
- D. `[]` and `[]`

**Answer: A.** The first value is numeric, while the quoted value is a string. Similar-looking values of different types do not compare as the same value.

### 12. What is a BSON Date best understood as?

- A. A point in time stored with millisecond precision
- B. A formatted sentence that has no numeric representation
- C. An ObjectId converted to a password
- D. A collection name

**Answer: A.** BSON Date represents a time value in milliseconds from the Unix epoch. A tool can display it in a readable date format.

### 13. What is the difference between a missing field and a field set to `null`?

- A. A missing field is absent; `null` is a present field with a null value.
- B. They always have identical meaning in every query and application.
- C. `null` means an empty string.
- D. A missing field is stored as an ObjectId.

**Answer: A.** The application and queries can distinguish an absent field from one explicitly set to null.

### 14. Why should an application use consistent types for a field such as `price`?

- A. Queries, validation, sorting, and calculations become easier to reason about.
- B. MongoDB requires every field in every collection to use one universal type.
- C. Consistency makes an ObjectId secret.
- D. It prevents documents from containing arrays.

**Answer: A.** A field should have a deliberate meaning and type. Mixing numeric prices with strings complicates comparison and calculation.

### 15. Which array is most predictable for a field named `tags`?

- A. An array whose entries are all strings
- B. An array that randomly mixes dates, passwords, and nested connection objects
- C. A value that changes between an object and a number for each document
- D. An array containing the collection itself

**Answer: A.** A stable element type makes validation and application code simpler.

### 16. An API receives an ID as a URL string. What should the server do before querying an ObjectId `_id`?

- A. Validate the string and convert it to an ObjectId using the database driver's supported API.
- B. Assume the string is already a BSON ObjectId.
- C. Use it as a database password.
- D. Convert every field in the document to a string.

**Answer: A.** HTTP parameters arrive as strings. Validate and convert only when the stored identifier is an ObjectId.

### 17. Why should an ObjectId not be treated as an authorization secret?

- A. It identifies a document but does not prove a caller has permission to access it.
- B. It always contains the user's password.
- C. It changes into a role after insertion.
- D. It cannot be used as a document identifier.

**Answer: A.** Authorization must be checked by the application for the authenticated user and requested resource.

### 18. Why can a JSON-like display be misleading when inspecting a MongoDB document?

- A. Different BSON types can have distinct representations even when their displayed text looks similar.
- B. The display always hides every field.
- C. MongoDB stores all values as plain strings.
- D. JSON-like syntax means the data is stored as an HTML page.

**Answer: A.** Inspect the actual value types when type distinctions matter; do not infer that every displayed value is a JSON string.

## Short-answer questions

### 1. What is BSON?

**Answer:** BSON is the binary serialization format MongoDB uses to represent document data. It has JSON-like structures and supports additional types such as ObjectId, Date, binary data, and distinct numeric types.

### 2. Why do MongoDB tools often show documents with JSON-like syntax?

**Answer:** It is a readable way to inspect data. The display does not mean MongoDB stores every value as plain JSON text.

### 3. How many hexadecimal characters are commonly shown for an ObjectId, and how many bytes does it represent?

**Answer:** It is commonly shown as 24 hexadecimal characters, representing 12 bytes.

### 4. What information is encoded in an ObjectId?

**Answer:** A 4-byte timestamp in seconds, 5 random bytes, and a 3-byte counter.

### 5. Why is an ObjectId only roughly ordered by generation time?

**Answer:** Its timestamp has one-second precision, and values can be generated on different machines or processes with different clocks and components. It is not a strict global sequence.

### 6. What should you store when you need an exact application creation or update time?

**Answer:** Store an explicit BSON Date field, such as `createdAt` or `updatedAt`, and set it according to the application's time-handling rules.

### 7. What happens to `_id` when a document is inserted without one?

**Answer:** MongoDB tooling or the driver generally generates an ObjectId and assigns it to `_id`. Applications can also supply a different unique identifier when appropriate.

### 8. Why are an ObjectId and its hexadecimal string not interchangeable?

**Answer:** They are different BSON types. A query using a string may not match a document whose `_id` is an ObjectId, even if the displayed hex characters are identical.

### 9. How should an API handle an ObjectId path parameter?

**Answer:** Treat the incoming value as a string, validate its format, convert it with the driver's ObjectId API, and handle invalid values cleanly. Do this only if the stored identifier is an ObjectId.

### 10. Does an ObjectId prove that the requester may read or change a document?

**Answer:** No. It identifies a document. The server must separately authenticate the user and authorize access to that document.

### 11. What is the practical difference between a missing field and a field with `null`?

**Answer:** A missing field has no entry in the document. A null field exists and explicitly stores a null value. Application logic, validation, and queries may treat them differently.

### 12. Why should a date usually be stored as a BSON Date instead of a formatted string?

**Answer:** A BSON Date has a time value that can be compared and sorted chronologically. A formatted string can be ambiguous and may sort lexically rather than by time.

### 13. Why should a numeric value such as a quantity not sometimes be stored as a string?

**Answer:** Mixed types complicate numeric comparisons, sorting, validation, and arithmetic. Keep the field's type consistent with its meaning.

### 14. What makes an array's shape predictable?

**Answer:** Its entries follow an intentional structure, often with a consistent element type. For example, a `tags` field can consistently contain strings.

### 15. Does MongoDB's flexible schema mean that an application should accept any field shape?

**Answer:** No. MongoDB can store documents with different shapes, but an application should still define and validate the fields and types it expects.

### 16. When is ObjectId's embedded timestamp useful, and when is it insufficient?

**Answer:** It can help estimate when an ObjectId was generated. It is insufficient as an exact event timestamp, ordering guarantee, or replacement for explicit `createdAt` and `updatedAt` fields.

### 17. What is a common type-related cause of an `_id` lookup returning no document?

**Answer:** The stored `_id` may be an ObjectId while the query uses a string with the same visible hexadecimal characters.

### 18. What should you inspect when a value looks right but a MongoDB query behaves unexpectedly?

**Answer:** Check the BSON type as well as the displayed value, and verify that the query uses the same type stored in the document.

## Review checklist

- Explain BSON and name types that standard JSON does not represent directly.
- Describe the ObjectId's 12-byte structure and 24-character hexadecimal display.
- Explain why ObjectIds are roughly ordered, not strict timestamps or global sequences.
- Distinguish an ObjectId from a string containing the same hexadecimal text.
- Choose appropriate types for dates, numbers, null values, and arrays.
- Explain why document shape should be consistent even when the schema is flexible.
- Validate and convert an incoming ID string only when the stored value is an ObjectId.
- Explain why an ObjectId does not provide authorization.
