# 020 - Create and read MongoDB documents: Questions and Answers

Use these questions to review inserting MongoDB documents, generated identifiers, reading one or many records, consuming cursors, projections, and handling failures. Answers include explanations so you can check both the result and the reason.

Related lesson: [020 - Create and read MongoDB documents](../lessons/020-create-and-read-mongodb-documents.md)

## Multiple-choice questions

### 1. Which Node.js driver method inserts one document?

- A. `courses.addOne(document)`
- B. `courses.insertOne(document)`
- C. `courses.findOne(document)`
- D. `courses.createArray(document)`

**Answer: B.** `insertOne()` is the driver's single-document insert operation. `findOne()` reads a matching document.

### 2. What happens when an inserted document does not provide `_id`?

- A. MongoDB rejects every insert.
- B. The driver creates an identifier for the document.
- C. The collection uses its name as the identifier.
- D. The document is inserted without an identifier.

**Answer: B.** The driver generates an ObjectId for a document that has no `_id`, and the insert result exposes it as `insertedId`.

### 3. Where can code get the ID generated by `insertOne()`?

- A. `result.insertedId`
- B. `result.document.title`
- C. `result.cursor`
- D. `result.collectionName`

**Answer: A.** The insert result contains the ID of the document that was inserted. The value can be used in a subsequent query.

### 4. What does `findOne(filter)` resolve to when no document matches?

- A. An empty cursor
- B. An empty string
- C. `null`
- D. `false`

**Answer: C.** Callers should check for `null` before accessing document fields.

### 5. What does `find(filter)` return?

- A. A cursor
- B. A single document or `null`
- C. A JSON string
- D. A write result

**Answer: A.** A cursor represents the query results and can be consumed with asynchronous iteration or methods such as `toArray()`.

### 6. Which is an appropriate way to read cursor results one at a time?

- A. `for await (const doc of cursor) { ... }`
- B. `cursor = await find()` followed by `cursor.map()`
- C. `for (const doc of await cursor) { ... }`
- D. `cursor.readAllImmediately()`

**Answer: A.** A MongoDB cursor supports asynchronous iteration. This avoids making an array of every matching result.

### 7. When is `toArray()` usually a reasonable choice?

- A. For a known-bounded result set, such as a page limited to 20 records
- B. For every collection regardless of its size
- C. Only when the collection is empty
- D. To convert a write result to an array

**Answer: A.** `toArray()` materializes the remaining cursor results in memory. Bound the result size when it is not already known to be small.

### 8. What can an empty filter passed to `find({})` match?

- A. No documents
- B. Every document in the collection
- C. Only documents with `_id: null`
- D. Only the newest document

**Answer: B.** An empty filter has no conditions, so it can return all collection documents. Avoid accidental unbounded reads in application endpoints.

### 9. What is a projection used for?

- A. Selecting which fields to return from matching documents
- B. Encrypting the connection URI
- C. Changing a read into an insert
- D. Creating a unique index

**Answer: A.** A projection shapes returned fields. It can reduce unnecessary data transfer and keep a response focused.

### 10. In an inclusion projection, what happens to `_id` by default?

- A. It is excluded automatically.
- B. It is included unless explicitly excluded.
- C. It becomes a string.
- D. It is replaced by the collection name.

**Answer: B.** MongoDB includes `_id` by default. An inclusion projection can explicitly set `_id: 0` to omit it.

### 11. Which projection is valid for returning only `title` and `level` while excluding `_id`?

- A. `{ title: 1, level: 1, _id: 0 }`
- B. `{ title: 1, level: 0 }`
- C. `{ title: 0, level: 1 }`
- D. `{ title: 0, level: 0, _id: 1 }`

**Answer: A.** Inclusion and exclusion fields cannot normally be mixed in one projection, with the special allowance that an inclusion projection may exclude `_id`.

### 12. A document stores `_id` as an ObjectId. Which filter type should identify it?

- A. The same ObjectId value
- B. Any string with the same characters
- C. A boolean
- D. A number containing its first digits

**Answer: A.** BSON types matter in filters. The hexadecimal text representation is not the ObjectId value itself; convert valid text to an ObjectId before querying.

### 13. What happens if `insertOne()` tries to insert an already-used `_id`?

- A. It silently updates the existing record.
- B. It fails with a duplicate-key write error.
- C. It changes the existing ID automatically.
- D. It skips the operation and reports success.

**Answer: B.** `_id` must be unique. Insert is not an update or upsert operation.

### 14. What is a useful reason to use `insertMany()`?

- A. Insert a finite, already-available batch of documents.
- B. Read one document by its ID.
- C. Stream an unlimited data source into one ever-growing array.
- D. Replace a connection pool.

**Answer: A.** `insertMany()` is suited to a bounded batch. Large imports should be designed around bounded chunks and explicit failure handling.

### 15. What is the default behavior of an ordered `insertMany()` batch when one write fails?

- A. The driver does not attempt later documents after the failure; earlier successful writes may remain.
- B. It rolls back every earlier document automatically.
- C. It retries all documents forever.
- D. It converts later documents into reads.

**Answer: A.** Ordered insertion stops at the failing item. Do not assume the whole batch was rolled back.

### 16. Why should application code avoid inserting a raw request body as a database document?

- A. It may contain unvalidated or unwanted fields.
- B. MongoDB only accepts arrays.
- C. Request bodies cannot contain strings.
- D. The driver always removes fields from objects.

**Answer: A.** Validate the input and explicitly select accepted fields. This prevents accidental storage of attacker-controlled or irrelevant properties.

### 17. What is the main concern with calling `toArray()` on an unbounded query?

- A. It can load an excessive number of results into application memory.
- B. It changes every field to a number.
- C. It deletes the matching records.
- D. It disconnects every MongoDB client.

**Answer: A.** Use a meaningful filter, pagination or limit, and cursor iteration for larger result sets.

### 18. Which statement about retrying an insert after a network error is safest?

- A. Retry blindly because the server definitely did not receive it.
- B. The server may have written it even if the client did not receive acknowledgement, so retry design should account for duplicate effects.
- C. Network errors always delete the collection.
- D. Every insert automatically becomes an upsert on retry.

**Answer: B.** A lost acknowledgement can make the outcome uncertain. Idempotency and the application's data model should guide retries.

### 19. Why should code await `insertOne()` or `findOne()`?

- A. The methods return promises that settle with a result or error.
- B. Awaiting converts MongoDB into an array.
- C. Awaiting creates a unique index.
- D. The methods are synchronous only when awaited.

**Answer: A.** These database operations are asynchronous. Awaiting them lets the code use the result and handle rejections in the correct order.

### 20. What should a web API do if `findOne()` returns `null`?

- A. Treat the missing document as a possible not-found case before reading fields.
- B. Access `document.title` anyway.
- C. Insert a random document automatically.
- D. Report that the query returned a cursor.

**Answer: A.** The application should handle the absence according to its API contract, rather than dereferencing `null`.

## Short-answer questions

### 21. What is the difference between `insertOne()` and `findOne()`?

**Answer:** `insertOne()` writes a document and returns a write result, including the inserted identifier. `findOne()` reads one matching document and resolves to that document or `null`.

### 22. Show a minimal single-document insert and print its generated ID.

**Answer:**

~~~js
const result = await courses.insertOne({
  title: "MongoDB fundamentals",
  level: "beginner"
});

console.log(result.insertedId);
~~~

If `_id` is omitted, the driver generates one and returns it in `insertedId`.

### 23. Why is `insertedId` useful immediately after a write?

**Answer:** It identifies the inserted document and can be used for a follow-up read, response, or later operation without searching by a possibly non-unique field.

### 24. What can happen if a document supplies an `_id` already present in the collection?

**Answer:** The insert fails with a duplicate-key write error because `_id` is unique. `insertOne()` does not update the existing document.

### 25. What does `insertMany()` return that helps inspect a successful batch?

**Answer:** Its result includes `insertedCount` and `insertedIds`. Those let the application inspect how many were inserted and the IDs associated with the input positions.

### 26. Why should a large import use bounded batches?

**Answer:** A bounded batch limits memory use and makes progress and failure recovery easier to manage. Building one enormous in-memory array can exhaust application resources.

### 27. Describe the default ordered batch behavior when one item fails.

**Answer:** The driver stops attempting later documents after the failing write. Documents inserted earlier in the batch may already exist, so do not assume all-or-nothing rollback.

### 28. What does `findOne()` return when it finds no matching document, and how should the caller use that result?

**Answer:** It returns `null`. Check for `null` before accessing fields, then handle the missing record according to the application's behavior.

### 29. Why does `findOne({ title: "Basics" })` not guarantee that the title is unique?

**Answer:** `findOne()` returns one match, but other matching documents may exist. Enforce uniqueness with a unique index if the data model requires it.

### 30. What does `find()` return, and what is the normal way to iterate its records?

**Answer:** It returns a cursor. Use asynchronous iteration such as `for await...of` or use `toArray()` for a small bounded result set.

### 31. Why is `toArray()` discouraged for an unbounded query?

**Answer:** It loads all remaining results into memory at once. A large collection can use excessive memory; iterate the cursor and bound reads instead.

### 32. What does `find({})` mean?

**Answer:** It has no filter conditions and can match every document in the collection. It should be intentional and bounded appropriately for application use.

### 33. How can a filter return a document by a generated ObjectId?

**Answer:** Use the ObjectId value itself: `await courses.findOne({ _id: courseId })`. If the ID arrived as text, validate it and convert it to an ObjectId before querying.

### 34. Why might `findOne({ _id: idString })` fail even if `idString` prints like the stored ID?

**Answer:** The string and the stored ObjectId are different BSON types. Convert a valid hexadecimal string to an ObjectId, and handle invalid input before sending the query.

### 35. How does an inclusion projection treat `_id` if it is not mentioned?

**Answer:** `_id` is included by default. Add `_id: 0` when the query should omit it while still including selected fields.

### 36. What is the exception to the rule against mixing inclusion and exclusion projections?

**Answer:** An inclusion projection may explicitly exclude `_id`. Other inclusion and exclusion fields should not be mixed in the same projection.

### 37. Give one reason to use a projection even when the application could receive full documents.

**Answer:** A projection limits returned fields, reducing unnecessary data transfer and preventing an operation from receiving fields it does not need.

### 38. Why should code build a document from accepted fields instead of inserting a request body directly?

**Answer:** Client input is untrusted. Selecting and validating fields prevents unexpected, sensitive, or malicious properties from being persisted.

### 39. What kinds of failures might a read or insert operation report?

**Answer:** Examples include duplicate-key or schema-validation write errors, network failures, and authorization errors. Code should catch failures where it can respond or log appropriately.

### 40. Why can an insert retry after a network error create a duplicate or repeated side effect?

**Answer:** The database may have completed the write while the client failed to receive confirmation. Retrying without an idempotency strategy can insert another record or repeat application effects.

### 41. What should an application avoid when logging a database error?

**Answer:** Avoid logging credential-bearing connection URIs, passwords, tokens, or other secrets. Log enough safe context to diagnose the failure.

### 42. Write a small bounded read for up to 10 published courses that returns only titles.

**Answer:**

~~~js
const titles = await courses
  .find(
    { published: true },
    { projection: { title: 1, _id: 0 } }
  )
  .limit(10)
  .toArray();
~~~

The filter narrows the records, the projection selects a field, and the limit bounds the array.

Try these without looking at the answers first:

1. Insert a document with a title, level, and creation date. Print its generated ID.
2. Read the document back by ID and handle the case where it is missing.
3. Insert three documents as one bounded batch and inspect the result.
4. Iterate published documents with a cursor instead of loading every result into memory.

6. Explain what happens if you run the same insert again with a fixed existing ID.
